# Validation protocol — EvoTwin-10X

This document is the **pre-registration** for the validation and generalisation
engine in [`danon/robustness.py`](../danon/robustness.py). It states, before any
new class of data is scored, what is tested, what threshold counts as passing,
what the release gate blocks on, and what none of it licenses anyone to claim.

It governs the layers this repository can score end to end today:

| Layer | Under test | Probes |
| --- | --- | --- |
| `danon.detect` change-point detector | Decisions and inputs over synthetic longitudinal series | `D1–D5` (data quality), `M1–M2` (measurement variation), `B1–B3` (biological variation), `F1–F3` (failure/safety) |
| The band the detector publishes | The nominal coverage of its "95%" state band | `U1–U4` |
| `danon.observer` ABC state estimator | Recovery, refusal and units contracts over CSF ctDNA VAF streams | `O1–O5` |
| `danon.variants` allele-fraction channel | The count contract, the pairing contract, depth invariance, and the mapping it publishes versus the ones it refuses | `V1–V5` |

**27 probes, all recorded.** Every probe writes its status *and the numbers that
decided it* into `outputs_real/robustness_record.json` (`robustness_record_v3`).

---

## 1. The gate

`release_gate()` returns `BLOCKED` if **any** probe reports `FAIL` or `ERROR`,
naming the offending probe ids; otherwise `PASS`.

- A probe that raises is `ERROR`, never a pass and never a skip.
- A probe removed from `PROBES` is a change to this protocol: the record
  version must be bumped so an old record cannot be mistaken for a new one.
- CI runs the matrix as a blocking step; a blocked gate fails the build.

Passing the gate does **not** mean the models are correct. It means each named
challenge was survived, with the numbers recorded.

## 2. Pre-declared thresholds

Set before data was scored, and only ever tightened afterward:

| Threshold | Value | Rationale |
| --- | --- | --- |
| Band calibration floor (`CALIBRATION_FLOOR`) | **0.80** | A band published as a 95% band must contain the true rate in at least 4 of 5 cases over 40 cases. A genuinely calibrated band clears this with margin (binomial tail below 32/40 at p = 0.95 is ~0.2%); a miscalibrated one fails by orders of magnitude. |
| Coverage floor under missingness (`U2`) | 0.80 | Same floor; a band that stays tight by ignoring what is absent is overconfidence, not precision. |
| Coverage floor under a misdeclared sigma (`U3`) | 0.80 | A wrong declared sigma is not evidence of precision: the band must not become *anti*-conservative. |
| Noise monotonicity (`U4`) | width(σ=6) > width(σ=2) | Three times the noise must not buy a narrower published band. |
| Observer recovery (`O1`) | planted `r0` inside the published credible band **and** width < 0.9 × prior | Recovery, not merely a number. |
| Observer degeneracy invariant (`O5`) | every `ESTIMATED` return has width < 0.9 × prior | The estimator's own stated criterion, mirrored as a constant so the probe checks the shipped rule. |

No threshold in this table may be relaxed after seeing a result. A threshold may
be **tightened** freely; changing one in the permissive direction requires a
recorded reason and a record-version bump, because that is a change in what the
gate means.

## 3. Splits and leakage

- All observations from one patient stay inside one split. Longitudinal
  duplicates are near-copies, and a boundary drawn through a patient leaks.
- Development, model-selection and final-evaluation data are distinct; the
  protocol is frozen before final results are inspected.
- Comparisons are against **simple baselines**, not only other complex models —
  the spatial forecast's competitors are persistence, margin dilation at
  several radii, and a matched-volume relocation null, scored on the observed
  growth (`danon/walkforward.py`).
- Every run records model version, dataset version, configuration and seed. The
  `PROVEN_FAILED` register (`danon/cure.py`) keeps failed experiments on the
  record rather than deleting them.

**Current state, stated plainly:** this repository holds **zero** engine-output
/ patient-outcome pairs, so there is no real-data evaluation to leak from and
none is claimed. There is no second-institution cohort in the tree, so the
"held-out institution" and "held-out time period" rows of the stress matrix are
**pre-registered and currently untestable** — they are a data-access boundary,
not a coding gap, and they are not counted as passed anywhere.

## 4. What is NOT established by a passing gate

- Nothing about real tumours: the probes are synthetic, generated by
  `danon.robustness` and `danon.detect.synthetic`, with no clinical data.
- No clinical utility, no patient benefit, no diagnostic claim. No output of
  this repository determines anyone's treatment.
- No generalisation beyond the tested distributions. "Held-out patients" is
  tested inside the synthetic generator; held-out institutions are not tested
  at all.
- No claim that the underlying biology is right. A probe can only show that an
  implementation does what its specification says — a wrong specification and a
  right one produce the same passing matrix.
- Nothing about outcomes, even now that real specimens are measured. The GLASS
  channel carries allele fractions and provable lower bounds on the fraction of
  tumour cells carrying a variant; it carries no purity, no copy number, no
  treatment record and no outcome, so a measured change is **not** evidence that
  therapy caused it, that a clone grew because it was resistant, or that any
  patient did better or worse. Measured molecular change is not clinical benefit,
  and the badges for `clinical_benefit` and `engine_predicts_patients` stay
  `UNKNOWN`.
- **A pair is an inference, not a recorded fact.** The release labels every one
  of its `693` specimen rows the same way, so timepoint is read from the
  specimen identifier (`TP`, `R1`–`R4`) and nothing in the data independently
  confirms the draw order, the interval between the two draws, or that a later
  specimen is a recurrence rather than a second primary or a re-biopsy of the
  same lesion. If that convention is wrong, the pairing is wrong and every number
  in the forecast moves. The check fails if the release ever declares a real
  timepoint column, because then the pairing must be re-derived from it.
- **A smaller-than-chance interval is not a small result.** Task A's resolved
  AUC of `0.71` is a modest molecular signal on one retrospective cohort: it says
  a variant's fraction in the primary carries some information about whether that
  locus is seen again. It says nothing about a patient, a treatment, or a
  trajectory, and an AUC compares two orderings inside this cohort rather than
  predicting an outcome for anyone.

## 6. Running it

```bash
python -m pytest tests/test_robustness.py -q          # the matrix's own tests
python - <<'PY'                                        # probe, record, gate
from danon.robustness import run_robustness_matrix, release_gate, write_robustness_record
results = run_robustness_matrix()
write_robustness_record(results, "outputs_real/robustness_record.json")
print(release_gate(results))
PY
```

Adding a probe: implement it in `danon/robustness.py`, register it in `PROBES`,
bump `RECORD_VERSION`, add its id to the class-coverage test, and record why it
exists. A probe is never added to make the matrix look complete — the observer
probes exist because a layer that replaces perfect information with an
estimator owes the same refusals as the layer it feeds.
