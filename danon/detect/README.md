# EvoTwin Phase 1 — evolutionary change detection (research-only)

A program that receives observations over time, estimates the tumour's
changing state, detects unexpected changes in its dynamics, and records how
accurate those detections are against known ground truth.

**Everything here runs on synthetic data. Nothing in this package touches a
patient, supports a treatment decision, or claims clinical benefit.** A
detector that performs well on data with known answers is ready for harder
tests — not automatically ready for patients.

## Reproduce the benchmark (exact command)

```
python -m danon.detect.cli --seeds 11 23 37 --n-cases 20 --out outputs_real/phase1_benchmark
```

Runs the detector over three held-out synthetic scenarios (60 cases),
scores every run against sealed ground truth, and writes:

- `benchmark_record.json` — machine-readable record: aggregates, per-run
  rows, and every missed change / false alarm **named by case id**,
- `benchmark_runs.parquet` — the run table for cross-experiment comparison,
- `benchmark_report.md` — the report with the run table and the
  limitations section, imported verbatim from the record,
- optional Plotly PNGs when `kaleido` is installed.

Run the tests:

```
python -m pytest tests/test_detect_phase1.py -q
```

## What is in the record (shipped defaults, seeds 11/23/37)

| metric | value |
|---|---|
| mean sensitivity | 0.978 |
| mean specificity | 0.800 |
| mean precision | 0.939 |
| false alarms per 1000 days | 0.55 |
| mean detection delay (call day − planted day) | 7.5 d |
| calibration rate (call within ±15 d of planted) | 0.749 |

The specific case ids the detector missed and falsely flagged in this sweep
are in `outputs_real/phase1_benchmark/benchmark_record.json`. The numbers
above are the record's own; the record is regenerated by the command and
byte-stable for a fixed seed list.

## Layout

| module | role |
|---|---|
| `schema.py` | Pydantic contract: timestamp, measurement kind, units, provenance; ground truth sealed in a separate book |
| `synthetic.py` | generator: planted changes, declared noise, missing observations, negative controls |
| `state.py` | rolling weighted log-linear state estimate with a 95% band and refusals |
| `detector.py` | sequential GLR change detector over weighted log-scale fits |
| `evaluate.py` | sensitivity / specificity / precision / FAR / delay / calibration, failures named |
| `benchmark.py` | multi-seed runner, machine-readable record, Parquet persistence |
| `report.py` | markdown report, Plotly figures |
| `cli.py` | the reproduce command |

## The leakage rule

The detector consumes an `ObservationStream` — a validated tuple of
measurements. The planted change, its day, its direction, and the
negative-control flag live in a **separate `GroundTruth` book** the detector
never receives; the evaluator is the only component that sees both, and its
scoring inputs are `DetectionResult` objects plus truth rows. The tests
demonstrate this structurally: deleting the truth book entirely changes no
detection, and shuffling case order changes no detection.

## The detector in one page

Log-radius is piecewise linear in day (the generator is exponential growth
with a rate change). After each new observation the detector fits one line
to all points and the best two-line split across all candidate days, by
weighted least squares with the **declared** per-reading sigmas as weights.
Because the weights are 1/σ², the weighted-SSE improvement between the
one-line and the best two-line fit is chi-square(1)-scaled under "no
change", so `sqrt(improvement)` is directly interpretable and the two
thresholds (confirm 4.5, suspect 3.2) are declared in `DetectorConfig`,
fixed before any scenario is generated, and never tuned on evaluation data.

Refusals are first-class: too few usable points, or points too weak to fit
two segments, produce `INSUFFICIENT_EVIDENCE` with a named reason — never a
confident guess. Nonpositive values are skipped (log undefined), not
imputed; missing observations simply do not appear as points.

## Limitations (what the report says, verbatim)

- Synthetic only: the generator is exp-growth in radius with a rate change,
  not a tumour model; sensitivity on this data says nothing about real
  imaging or liquid-biopsy series.
- Single change per case: no multiple-change, no gradual-drift, and no
  regression-to-baseline scenarios are in Phase 1.
- Call-level, not event-level metrics: precision counts flagged CASES, and
  a case can only flag once in this version.
- The detector knows the generative family (exp-growth, log-linear); a
  model violation is out of scope and would need a new baseline.
- Calibration is scored only for confirmed calls with a planted day;
  suspected-only calls lower sensitivity but are not delay-scored.
- No clinical claim of any kind: the report describes a controlled
  synthetic experiment; no patient benefit is implied or measured.

## Explicitly out of scope

Patient-specific treatment recommendations, clinical dosing optimisation,
and any claim of clinical efficacy are out of scope for this package and are
not implemented anywhere in it. Synthetic benchmark performance is not
evidence of patient benefit and the record never presents it as such.
